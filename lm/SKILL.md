# 로컬 → Main

## 공통 계약

- **현재 작업 중인 프로젝트**의 원래 폴더를 대상으로 한다. 스킬 설치 폴더나 특정 프로젝트 경로를 작업 대상으로 삼지 않는다. 경로·Git 루트·현재 브랜치·원격·미커밋/미푸시 변경과 AGENTS.md, 프로젝트 배포 규칙, 기존 CI/CD를 먼저 확인한다. 여러 프로젝트 중 대상이 불명확할 때만 질문한다.
- 실행 요청은 해당 명령의 커밋·푸시·PR 병합과 연결된 Git 배포를 승인한 것이다. 스킬 생성·설명 요청은 실행 요청이 아니다. 같은 범위의 승인을 반복해서 묻지 않는다.
- 기본 브랜치 이름은 `preview`와 `main`이다. 프로젝트에서 지정한 이름·원격·PR 정책이 있으면 따른다. 필요한 브랜치가 없다면 기준 커밋이 명확할 때만 만들며, 소스 선택이 모호하면 질문한다. 기존 worktree를 자동 선택하거나 새로 만들지 않는다.
- 모든 로컬 변경에는 staged/unstaged/untracked 코드·설정·문서·필요 자산·삭제·미푸시 커밋을 포함한다. 내용을 검토하여 파일별로 stage하고, 비밀키·세션·개인 영수증·빌드·캐시·런타임 자료는 일괄 업로드하지 않는다. 애매한 자료만 확인하고 제외 목록을 보고한다. 이 스킬만 요청했다고 기존 변경을 버리거나 일부 변경을 몰래 누락하지 않는다.
- 검증 명령은 프로젝트에서 발견한 테스트·린트·빌드와 관련 동작 검사를 사용한다. npm/Next/Vercel을 가정하지 않는다. 토큰·비밀번호를 출력하지 않는다. 같은 소스 SHA·환경에서 이미 성공한 검증은 재사용할 수 있다.
- 원격을 fetch해 통합하고 동시 변경을 보존한다. force push, reset --hard, 훅 우회, 보호 해제, 실패 검사 무시, 로컬 소스 업로드 배포를 사용하지 않는다. 원격 head가 바뀌면 새 diff와 SHA를 재검증한다.
- 기존 Git 배포가 연결되어 있으면 해당 환경의 완료 상태·소스 SHA·주요 화면을 확인한다. CI/CD가 없으면 새 배포 서비스를 임의로 만들지 말고 Git 반영 결과만 보고한다. 인증·요금제·실패로 검증하지 못한 항목은 성공과 구분하며 같은 실패를 무한 재시도하지 않는다.

## 실행

1. main 반영 경로를 프로젝트 규칙에서 확인한다. **preview 경유가 필수라면 설치된 `lpm` 스킬을 읽고 실행한다.** lm은 중간 검증을 생략하거나 main 직접 push를 허용하는 명령이 아니다.
2. preview 경유 규칙이 없다면 현재 작업 브랜치를 main 대상 PR의 head로 사용한다. 현재 main에서 작업 중이면 필요한 변경·미푸시 커밋을 보존하여 `codex/` 접두사의 작업 브랜치로 옮긴다. 새 worktree는 만들지 않는다.
3. 모든 로컬 배포 대상 변경을 검토·검증·커밋하고 작업 브랜치에 push한다. 같은 저장소 작업 브랜치 → main PR을 재사용/생성한다. 프로젝트가 요구하는 검사·리뷰와 검증된 head SHA를 확인한 뒤 PR로 병합한다. 관리자 우회·main 직접 push는 하지 않는다.
4. fetch 후 local main을 원격 main에 fast-forward하고 연결된 운영 Git 배포의 완료·SHA·화면을 확인한다. 동시 변경은 보존한다. 현재 작업 브랜치는 프로젝트의 일상 작업 규칙에 맞춘다.
5. 실제 사용한 경로(예: 로컬 → preview → PR → main), PR·커밋·검증·제외/잔여 변경을 보고한다. 필요한 PR 호스트 기능이나 검증 권한이 없으면 직접 push로 우회하지 않는다.
